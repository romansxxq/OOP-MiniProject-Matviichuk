# План ітерації 2

## Сценарії з backlog, які беремо в реалізацію
- Реєстрація нового пацієнта в базі.
- Призначення лікаря до конкретного відділення.
- Створення запису на прийом з перевіркою доступності часу.

## Класи з Lab 34, які залишаються без суттєвих змін
- AppointmentStatus (перелік статусів).
- Nurse (поведінка без змін).
- Result (базова ідея результату операції).

## Заплановані точки розширення
- Strategy для валідації записів (додавання нових правил без зміни сервісу).
- Factory для створення медперсоналу.
- IDataStore для підміни способу збереження (JSON сьогодні, XML/БД завтра).

## Ризики
- Дублювання бізнес-логіки між сервісами та консольним меню.
- Слабкі контракти репозиторіїв можуть ускладнити тести та persistence.
- Конфлікти даних під час відновлення стану (дублікати ID, неіснуючі посилання).
- Зростання кількості сценаріїв потребує стабільних тестів і ізольованого I/O.
